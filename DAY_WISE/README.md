# Day-wise Learning Records

One Markdown record per bootcamp day. A day is a curriculum unit, not a one-session deadline. Keep unfinished syllabus items visible across chats.

Each day record captures exact syllabus topics/status, lesson notes/examples, commands demonstrated vs actually run, guided and independent practicals/evidence, quiz and interview preparation, revision needs, blockers and exact continuation point.

Use the same progress labels as SYLLABUS_TRACKER.md. Do not mark a day complete until its syllabus, practicals, quiz and interview preparation have been addressed.


## Visual lesson authoring checklist

Use visuals to clarify each day's concepts while retaining every syllabus item and the complete practical requirements.

- [ ] Add a focused Mermaid flowchart/state diagram/sequence diagram/commit graph where it genuinely helps.
- [ ] Apply the shared color legend: blue worktree, amber staging, green commits/verification, purple remote/collaboration, red risk/conflict.
- [ ] Include relevant technical images or annotated screenshots only where they add information; add alt text and redact private data.
- [ ] Use short instructional GIFs only when motion is essential, and include a static alternative.
- [ ] In ChatGPT lessons, use interactive knowledge checks/progress indicators when useful; in Markdown, use static quizzes/checklists and do not claim they are interactive widgets.
- [ ] Present terminal demonstrations as context, command, expected output and explanation. Label expected output as illustrative.
- [ ] Keep learner-run evidence separate from instructor demonstrations.
- [ ] Finish with practice, troubleshooting, interview questions and revision—not visuals alone.

See the visual teaching standard in [MASTER_COURSE_PLANNER.md](../MASTER_COURSE_PLANNER.md).
