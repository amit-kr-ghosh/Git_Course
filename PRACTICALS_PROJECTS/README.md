# Practical Projects

Track the eight-project ladder from MASTER_COURSE_PLANNER.md. Within each project folder, create topic-wise study notes under TOPICS/ as each project concept/implementation topic is fully taught. Keep the project brief, implementation guide and evaluation/evidence record distinct. A concise project REVISION-SUMMARY.md may be added after all planned project topics have been taught. Do not create notes for untaught material or imply instructor demonstrations are learner evidence. For each project record objective, requirements, safe workflow, repository/path, steps attempted, result, evidence, review feedback and definition-of-done status.

Keep risky history experiments in disposable repositories. Create separate project repositories only when useful; do not create them automatically.

## Project screenshot and evidence assets

- Store project walkthrough/reference captures under `PRACTICALS_PROJECTS/assets/`, creating the folder only when needed.
- Link screenshots from the relevant project record using relative paths, descriptive alt text and a concise caption.
- Use authentic GitHub UI captures for repository settings, pull requests, reviews, Actions runs and releases when useful. Clearly label instructor-created mock-ups or illustrative terminal output.
- Treat project deliverable screenshots and learner evidence separately. Only learner-supplied, reviewable evidence can support a Practised/Verified status; an instructor demonstration never proves learner completion.
- Redact usernames, email addresses, private repository data, tokens, keys and credential-bearing URLs. Credit external assets and check licences.
- Prefer editable Mermaid for workflow/commit diagrams; use GIF only when motion adds instructional value and include a static alternative.
- Verify every relative image link and rendered asset after committing. Keep only assets that support project requirements or evaluation.
